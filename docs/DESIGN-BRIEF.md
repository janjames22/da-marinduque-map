## 1. Summary

- **The PDF report matches the data in the system.** All 199 records, the type split and every municipality's count agree ([§2](#2-data-reconciliation)). No re-import is needed.
- **27 records stay off the map** until the region verifies their location: 26 with no coordinates and 1 with coordinates outside Marinduque.
- The dashboard already counts those 27 records. It has nowhere that names them, and it drops them when "Only the current map view" is on. Phase 13 fixes both.
- The brief fixes the sidebar and addresses ([§4](#4-routes-and-navigation)), lists 36 screens and dialogs with the states each needs ([§5](#5-screen-inventory)), and specifies the content of the two new pages, Home and Dashboard ([§6](#6-home-page-content), [§7](#7-dashboard-page-content)).
- The owner made three decisions ([§3](#3-decisions)): the system is called "Intervention Map", everyone lands on Home, and it stays separate from agri-dms with the same design.

## 3. Decisions

Decided by the owner on 2026-11-11.

| # | Question | Decision | Why |
|---|---|---|---|
| D-1 | What does the sidebar call the system? | **"Intervention Map"**, with "Marinduque PAO" underneath, in agri-dms's logo tile | The two systems read as one family. Each one's name says what it does |
| D-2 | Where does each person land after signing in? | **Home, for everyone** | One rule is simpler to explain. The map is one click away, and Home shows Viewers the headline numbers at once |
| D-3 | Will this system sit inside agri-dms later? | **Stay separate, with the same design.** Keep it ready to become a module | The spec already asks for a module that can later join the ABE Project Data Consolidation System. Merging now would mean a shared login and database, which is out of scope |

## 6. Home page content

Order from top to bottom:

| # | Block | Content | Who sees it |
|---|---|---|---|
| H-1 | Welcome banner | "Welcome, {name}". One line: "Figures come from every record in the system, including those not yet on the map." Buttons: Open dashboard, View the map, Add intervention (Encoder and Admin only) | Everyone |
| H-2 | Work waiting | One row per item, each a link: records needing QA, units with no condition yet, records waiting for verified coordinates. Rows with nothing waiting are hidden. The block is hidden when all are clear | Encoder, Admin |
| H-3 | Headline tiles | Interventions (dark hero tile), Beneficiaries (approximate), Barangays reached (n of 218), % operational | Everyone |
| H-4 | One card per type | **Farm Machinery:** units, % operational, a segmented bar of category groups. **SSIP:** units and status. **FMR:** "Data to follow" | Everyone |

## 7. Dashboard page content

### Filter bar

Program, year funded from and to, municipality, and the custom field filters that exist today. The filters stay in step with the map, the records list and the exports, as they do now (`state/map-ui`).

### KPI tiles

| # | Tile | Value | Note under the value | Exists today |
|---|---|---|---|---|
| K-1 | Total interventions (hero) | Records | Units if they differ | Yes |
| K-2 | Farm Machinery | Units | | Yes, as a type tile |
| K-3 | SSIP | Units | | Yes, as a type tile |
| K-4 | Farm-to-Market Roads | "Data to follow" | Becomes count and km in Phase 16 | **New, placeholder** |
| K-5 | % operational | Percent of assessed units | Units not assessed | Yes |
| K-6 | Beneficiaries (approx.) | Distinct names | How names are compared | Yes |
| K-7 | Barangays with no intervention yet | Count | "of 218" | Yes |
| K-8 | Awaiting coordinate verification | Count | Share of all records, link to C-7 | **New** (NC-2) |

"Records needing QA" moves from the dashboard to Home's Work waiting block, because it's a task, not a figure for a report.

### Charts and tables

Every chart card has a title, a one-line note, a Table button and a CSV button, as in agri-dms.

| # | Card | Form | Exists today |
|---|---|---|---|
| C-1 | Units by category group | Segmented bar, like agri-dms's "Growth stage mix" | **New**, from the category groups already in the data |
| C-2 | Units by municipality | Bar. Selecting a bar filters to that municipality | Yes. Selecting is new |
| C-3 | Status by municipality | Stacked bar | Yes |
| C-4 | Units by program | Bar | Yes |
| C-5 | Units by year funded | Bar, with the count of units with no year | Yes |
| C-6 | Units by category | Bar, top 15 | Yes |
| C-7 | Awaiting coordinate verification | Table: ID, type, item, beneficiary, municipality, encoded barangay, issue. Grouped by municipality. CSV in the field-verification sheet's columns | **New** (NC-3, NC-4) |

### Rules

- Totals include records without coordinates (NC-1). They already do today.
- **When "Only the current map view" is on**, records without coordinates can't be in any view. The dashboard then says: "{n} records without coordinates are left out because only the current map view is counted." This applies to the map's summary panel. The Dashboard page has no map view to limit to.
- A filter that matches nothing shows the empty state, not zeroes.
